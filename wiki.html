    [Rule] CPP Coding Conventions

    Jump to bottom
    Do_Suha edited this page Apr 2, 2025 · 3 revisions

    소개

    Project Vanishing Ground에서 사용하는 C++ 언어의 Coding Conventions에 대해 정리한 Wiki입니다. 특정 Convention을 찾으실 때에는 Ctrl + F를 사용하면 좋습니다.

    목표

    Project Vanishing Ground의 C++ Conventions의 목표는 다음과 같습니다.

    가독성의 증대

    저희는 Team Project를 진행하면서 동료들의 코드를 읽거나 동료들에게 자신이 작성한 코드를 공유하며 소통하기를 바랍니다. 이러한 소통의 과정에서 서로의 코드가 마치 자신이 작성하는 것처럼 읽을 수 있다면 코드 분석 시간도 감소할 뿐더러 본질적인 기술적 대화에 더 많은 시간을 할애할 수 있고 더 나아가 동료의 코드를 신뢰함으로서 협업이 매끄럽게 진행되는 것을 기대할 수 있습니다.

    수정의 용이

    동료가 작성한 코드를 수정해야 할 때가 올지도 모릅니다. 심지어 자신이 작성한 코드도 1-2달이 지나면 코드를 다시 분석하는 데에 많은 시간이 소요됩니다. Coding Convention은 자신 또는 동료가 작성한 코드를 다시 수정해야 할 경우 코드를 직관적으로 파악하고 빠르게 수정하여 버그를 해결하는 데에 원활하도록 도와줍니다.

    예측 가능한 API

    체계적으로 작성된 Coding Convention은 API에 대하여 항상 Document를 참조하는 것이 아니라 해당 기능을 예측하게 도와주고 또한 API가 존재하는 지에 대한 여부도 Code 작성 시기에 확인 할 수 있도록 합니다. 이는 개발 속도를 빠르게 만들며 필요하나 존재하지 않는 API에 대한 빠른 피드백을 할 수 있도록 합니다.

    원활한 디버깅

    좋은 Coding Convention은 디버깅을 수월하게 진행하도록 만든다고 믿습니다. 명시적 타입 작성, 좋은 명명 규칙, 함수 Signature의 일관성은 코드를 작성하고 사용할 때 뿐만 아니라 타입에 맞는 대입, 이름에 어울리는 값, 매개변수의 전달 등 Convention과 Data를 비교하며 디버깅을 진행할 수 있습니다.

    추가 요청

    추가로 필요한 Convention이 있으면 여기에 추가해주시면 됩니다.

    • 예시) 지역 변수
    • 멤버 변수 초기화 방법 (25/03/31 추가)
    • enum scope 제한 (25/03/31 추가)
    • 디버깅 친화 코드 (25/03/31 추가)
    • 리터럴 비교 코드 안정성 (25/03/31 추가)
    • 매직 넘버 (25/03/31 추가)
    • Folder 방식 (25/04/02 추가)
    • 접근 한정자 (25/04/02 추가)
    • static & extern 키워드 (규칙 없음: 용도에 맞게 사용)
    • Global 변수 스타일 변경 (25/04/02 수정)
    • namespace 규칙 (25/04/02 추가)

    요약

    // Coding Conventions Cheat Sheet

// Macro
#define MY_MACRO(x, y) ((x) + (y)) // use inline function instead

// Constant Macro
#define CONSTANT_MACRO 10; // use constexpr instead

// Namespace
namespace MyNamespace
{
    // Using Declaration
    using MyType = int;
    typedef int MyType;

    namespace Global
    {
        // Global Variant
        int globalVariant;
    }

    // Struct
    struct MyStruct
    {
        // Field
        int StructField;
    };

    // Interface
    struct IMyInterface
    {
        // InterfaceFunction
        virtual void InterfaceFunction() = 0;
    };

    // Function Object
    struct FunctionObject
    {
        int operator()(const int myParameter) const
        {
            return myParameter;
        }
    };

    // Class
    class MyClass
    {
    public:
        static constexpr int COMPILE_TIME_CONSTANT = 20;

        MyClass() = default;

        // Member Function
        int MemberFunction() const
        {
            return _myPrivateMember * 2;
        }

        // Getter
        int GetMemberVariant() const
        {
            return _myPrivateMember;
        }

        // Setter
        void SetMemberVariant(const int myParameter)
        {
            _myPrivateMember = myParameter;
        }

        // Get State Managed Pointer
        int* GetStatePointer() const
        {
            return _statePointer;
        }

        // Create Allocated Data
        void CreateAllocatedData(int** pointerContainer)
        {
            *pointerContainer = new int;
        }

        // Public Member
        int MyPublicMember;

    private:
        // Private Member
        int _myPrivateMember;

        // State Managed Pointer
        int* _statePointer;
    };
}

    코드 스타일

    간격

    코드 시작

    • 코드 시작 간격은 띄어쓰기 4개로 한다.
    int Function()
{
    // Any Code Start
}

    줄 바꿈

    코드 블록 괄호

    • 코드 블록 괄호는 줄을 바꿔서 작성한다.
    int Function()
{
    ...
}

    한 줄 if문

    • retrun, break, continue 등 단순 명령어만 if문 (+ if else, else)을 축약해서 한 줄로 작성 할 수 있다.
    void Function(int* pointer)
{
    if (pointer == nullptr) return;
}

    길어진 if 조건

    • if의 조건이 길어질 때에는 조건마다 줄 바꿈을 할 수 있다.
    • 다만 이때 모든 매개변수를 줄 바꿈 해야한다.
    // bad
if (condition1 == true, condition2 == false,
    condition3 == true, condition4 == false)
{
    ///
}

// good
if (condition1 == true, condition2 == false, condition3 == true, condition4 == false)
{
    ///
}

// good
if (condition1 == true,
    condition2 == false,
    condition3 == true,
    condition4 == false)
{
    ///
}

    길어진 매개 변수

    • 매개 변수가 길어질 때에는 매개변수마다 줄 바꿈을 할 수 있다.
    • 다만 이때 모든 매개변수를 줄 바꿈 해야한다.
    // bad
int a = Function(parameter1, parameter2, 
                 parameter3, parameter4);

// good
int a = Function(parameter1, parameter2, parameter3, parameter4);

// good
int a = Function(parameter1,
                 parameter2,
                 parameter3,
                 parameter4);

    작성 요령

    Getter & Setter & Factory

    • Getter 함수는 앞에 'Get' 접두사를 반드시 붙인다.
    • Setter 함수는 앞에 'Set' 접두사를 반드시 붙인다.
    • Factory 함수(내부에서 동적 할당 후 반환)는 'Create' 접두사를 반드시 붙인다.
    • 위 내용을 지킬 수 없는 함수는 분리하여 작성한다.

    Boolean

    • Boolean 타입의 변수는 종류를 불문하고 앞에 'is', 'was', 'can' 등 상황에 맞는 접두사를 반드시 붙인다.
    • Boolean 타입을 반환하는 Getter 함수는 앞에 'IS', 'Was', 'Can' 등 상황에 맞는 접두사를 반드시 'Get'대신 붙인다.
    class MyClass
{
public:
    bool IsActive
    {
        return _isActive;
    }
private:
    bool _isActive;
}

    매크로

    • 매크로는 특별한 경우(코드 생성 등)가 아니면 작성하지 않는다.
    • 매크로 함수는 inline 또는 static 함수로 대체하여 사용한다.
    • 매크로 상수는 constexpr로 대체하여 사용한다.

    타입 재정의

    • 타입 재정의는 typedef 보다 using을 사용한다.
    typedef int MyType; // bad
using MyType = int; // good

    포인터의 구분

    • 상태가 관리되는 포인터에 대한 Getter는 반환 타입에 포인터 타입을 작성한다.
    • 상태가 관리되지 않는 포인터에 대한 Create는 매개변수에 Double Pointer 타입으로 작성한다.
    • 이때 Create 함수를 호출한 Caller는 해당 Pointer의 해제 책임이 있다.
    class Manager
{
public:
    int* GetHandle()
    {
        return _handle;
    }

    void CreateResource(int** handle)
    {
        *handle = new int();
    }
private:
    int* _handle;
}

    enum

    • enum을 구분 용도로 사용한다면 enum class를 사용하도록 한다.
    • enum을 상수 용도로 사용한다면 namespace와 staic constant variable을 사용하는게 좋다.
    • 다만 class 내부와 같이 namespace를 선언 할 수 없다면 enum을 그대로 사용한다.
    • enum의 scope는 다음과 같이 정의한다.
    • 해당 객체에서만 사용하는 열거형일 경우 해당 객체의 class 내의 private 한정자로 선언한다.
    • 해당 객체 외에서 사용하게 되는 경우 'Declare.h'등의 파일을 생성하여 한 곳에 선언하여 보관한다.
    // bad
enum Device
{
    MOUSE,
    KEYBOARD,
    CONTROLLER
}

// good
enum class Device : unsigned char
{
    MOUSE,
    KEYBOARD,
    CONTROLLER
}

// good
enum InitializeFlag : unsigned char
{
    FLAG1 = 1 << 0,
    FLAG2 = 1 << 1,
    FLAG3 = 1 << 2
}

// better
namespace InitializeFlag
{
    static constexpr unsigned char FLAG1 = 1 << 0;
    static constexpr unsigned char FLAG2 = 2 << 0;
    static constexpr unsigned char FLAG3 = 3 << 0;
}

    초기화

    • 멤버 변수 초기화는 Member Initialize List를 사용하여 초기화 한다.
    • 생성자에서 초기화를 하면 상황에 따라 다른 값을 사용하여 초기화를 할 수 있다.
    • 상속 받은 클래스는 부모의 클래스의 멤버 변수를 초기화 할 수 있다.
    • 생성자는 다른 생성자를 호출하여 초기화를 간략화 할 수 있다.
    • 초기화 구문이 다른 곳에 혼재되어 있으면 초기화 되어 있는지에 대한 여부를 판단하기 힘들어진다.
    • 기타 변수 초기화는 Uniform Initialize를 사용하여 초기화 한다.
    class MyClass
{
public:
    MyClass() : _memberVariant{0}
    {
    }

    MyClass(int parameter) : _memberVariant{parameter}
    {
    }
private:
    int _memberVariant;
}

    비교

    • RValue와 LValue를 비교 하는 경우 RValue를 비교 연산자 좌측에 작성하여 코드 안정성을 향상시킨다.
    • 비교할 것 이 많은 경우 비교 비용이 적은 것을 먼저 비교한다.
    • true / false와 비교 하는 경우 생략 또는 부정(!)을 하지 않는다.
    // good
if (nullptr == pointer)
{
    ...
}

// bad
if (condition)
{
    ...
}

// good
if (condition == true)
{
    ...
}

// bad
if (IsCondition1() == true, condition2 == false)
{
    ...
}

// good
if (condition2 == false, IsCondition1() == true)
{
    ...
}

    매직 넘버

    • 매직 넘버(값의 출처를 알 수 없는 Literal)는 사용하지 않는다.
    • 다만 반드시 사용해야만 하는 경우 주석을 통해 출처 또는 이유를 남긴다.
    // bad
int remain = parameter % 2;

// good
constexpr int EVEN_CHECKER = 2;
int remain = parameter & 2;

// better
bool IsEven(int value) 
{
    return (value % 2) == 0;
}
bool isEven = IsEven(parameter);

// good
short initializeFlag = 3; // MSDN(https://msdn.microsoft.com/...)

    디버깅 친화

    • 연속된 멤버 액세스 연산자를 사용하는 경우 분리하여 지역 변수에 저장한다.
    // bad
int data = System->GetModule()->GetDatabase()->GetData();

// good
Module* module = System->GetModule();
Database* database = module->GetDatabase();
int data = database->GetData();

    접근 한정자

    • class의 멤버 변수는 private으로 선언해야 합니다.
    • 멤버 변수의 값 변경 또는 값 접근은 Getter & Setter를 사용합니다.
    // bad
class MyClass
{
public:
    int MyMember;
}

// good
class MyClass
{
public:
    int GetMyMember() const
    {
        return _myMember;
    }

    void SetMyMember(int myMember)
    {
        _myMember = myMember;
    }
private:
    int _myMember;
}

    namesapce 규칙

    • 모든 프로젝트는 자신만의 고유한 namespace를 가져야 한다.
    // bad
class MyClass
{
}

// good
namespace MyProject
{
    class MyClass
    {
    }
}

    Folder 방식

    • 붉은색 원으로 표시되어 있는 아이콘을 누르면 Folder 방식을 사용할 수 있습니다.
    • Visual Studio에서 제공하는 Filter 방식은 사용하지 않고 Folder 방식을 사용합니다.
    • Folder 방식은 다음과 같은 장점이 있습니다.
    • 실제 폴더 구조와 동일하여 관리가 용이함
    • GIT, SVN 등 소스 관리 시스템과 호환성이 좋음
